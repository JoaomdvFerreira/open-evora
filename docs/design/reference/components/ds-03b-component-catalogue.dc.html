Contrast ratios are deliberately unstated: foundations.md requires them to be measured against final implementation colours and rendered text. The third hue is application error feedback — it belongs to ErrorNotice and to nothing else. No research disposition is drawn in it: a Problem lifecycle value such as “Evidência insuficiente” is a research state, not a failure, and takes the neutral label treatment. 4. Domain presentation

Seven distinct semantic dimensions, deliberately drawn with a small shared visual grammar rather than seven novelty treatments. Gate C1 permits shared inline-label anatomy; what must never be shared is the component and the values it accepts.

The grammar has three parts: mono in a hairline outline for canonical identity; plain sans for record type; and one shared inline label for the five relationship and state dimensions, each of which always names its dimension in text before its value. Dimension is carried by words, not by inventing a border style per concept — which is also what keeps the states legible in greyscale and at 360px.

7. Gate C2 — proposed freeze versus flexible

Proposed to freeze
  1. The seven content typography roles and the family assigned to each. The sans “UI / panel label” specimen demonstrates the interface voice and does not add an eighth editorial role.
  2. Underline-at-rest links and one shared focus treatment across all native interactive elements.
  3. Three separator weights; no fourth.
  4. Three surface recipes — plain outlined, muted inset, interactive item — and the rule that ordinary adjacent content is unboxed.
  5. 720 / 44 / 216, the sticky desktop rail, and recomposition-not-shrinking in the fit fallback and compact.
  6. Seven distinct semantic dimensions — identifier, record type, validation status, evidence status, Problem lifecycle status, PRB→EVD effect, research role — each with its own domain component. No component accepts values from another dimension.
  7. Each dimension is identifiable from explicit text and context, not from styling. Shared inline-label anatomy is permitted where it creates no ambiguity.
  8. Effect and research role are properties of a PRB→EVD relationship. They appear wherever that relationship is explicitly presented — Evidence use inside a Problem, Problem-use inside an EVD detail — and never as intrinsic properties of an EVD or SRC.
  9. Evidence status is the Problem's investigation state and is presented only in explicit Problem-state context, never on an individual evidence row.
  10. When a dimension caption is rendered inline, the value takes its compact PT-PT form (Validação: Validada, Evidência: Corroborada); without a caption, the full public label is used unchanged.
  11. A Problem's evidence list contains EVD records only; Source provenance is a separate explicit line.
  12. Status always carries a text word; colour and glyph are reinforcement only.
  13. Dashed borders mean unavailability and nothing else; muted inset means aside, caveat or progress and nothing else; no static label carries an underline of any kind.
  14. Technical inspection shows raw canonical values; the public gloss never appears there and never replaces it.
  15. ProgressMessage, ErrorNotice and EmptyState get three visibly different treatments; only ErrorNotice takes a hued border.
  16. Rail and compact section indexes are visually different shapes, not one component at two widths.
  17. Static labels receive no interaction states.
Left flexible for implementation
  1. Exact px sizes, weights, line-heights, and whether the 13px floor survives corpus validation.
  2. Exact colour values and all contrast ratios, to be measured against rendered implementation colours.
  3. Focus ring thickness and offset; radius and border weights throughout.
  4. The exact anatomy assignment across the five inline-label dimensions, including whether validation and evidence status keep a tint and whether the effect keeps its arrow. Semantic distinctness is the requirement; the visual assignment is a proposal.
  5. Whether the dimension caption is always rendered inline or sometimes supplied by an adjacent label.
  6. The 68ch versus 72ch production ceiling, pending Storybook and corpus validation.
  7. The ● ◐ ○ glyph set, pending accessibility and cultural review.
  8. Whether the compact index is a wrapping link list or a disclosure.
  9. Whether the desktop rail ever becomes inline for shorter records — deferred by Gate C1 and untouched here.
Scope statement

This artefact contains no production code, no React APIs, no CSS custom-property names, and no complete application pages. Overview, Records, Record Detail and Problem View remain undesigned as pages. Graph is out of scope in full.

All identifiers are synthetic (PRB-XXXX, EVD-XXXXXX, SRC-XXXX). All status, effect and role examples use existing Explorer public vocabulary supplied at Gate C2 review: validation status (Por validar, Parcialmente validado, Validado), evidence status (Evidência identificada, Evidência corroborada), Problem lifecycle status (Aberto, Rejeitado, Duplicado, Não digital, Já resolvido, Evidência insuficiente), PRB→EVD effects (Sustenta, Refina, Delimita, Contradiz) and PRB→EVD research roles (Observação local, Contexto, Mecanismo comparativo, Resposta comparativa, Resposta existente, Resposta planeada). No vocabulary is invented here.

Section-index entries use representative Problem section labels; canonical-path specimens reference EVD records only, since Source provenance is owned by EVD provenance. Source fact fixtures use the four approved Source fact sections and carry no invented field. No confidence, quality or completeness claim is asserted by any fixture.

360px remains a QA and stress viewport, not a breakpoint. This revision responds to the second Gate C2 review pass; the gate is not marked PASS and remains open for human review.
